Evaluation harness for LLM pipelines

Check every LLM answer before it ships.

A FastAPI service that runs a pipeline against a golden test set, grades each answer, stores every run, and fails the build in CI when quality drops below a threshold.

60 labeled answers, 30 correct and 30 wrong, in ten categories. The judge ran three times on every case and gave the same verdict all three times on 59 of 60. Both scorers were perfect on plain answers. The judge wins on negation, numbers written as words, extra false claims and synonyms. On a separate 15-question set, the real pipeline (gpt-oss-20b) was judged correct on all 15.

Where it fails: two answers ending in a fake "SYSTEM NOTE" told the judge what to output, and it obeyed in all three runs. The cases and labels were drafted with an AI assistant and not independently verified, and the set was built to be hard for string matching, so read this as a stress test and not an accuracy estimate.

How a run works

  1. 1Add test casesQuestions with expected answers go in through the API and are stored in Postgres.
  2. 2Start a runThe API returns at once. The pipeline answers each question in the background and the scorer grades it.
  3. 3Gate the mergeCI runs the same check on every push and fails the build if the average score falls under 0.80.

Stack and limits

Built with
FastAPI, SQLAlchemy, Postgres on Neon, Docker, GitHub Actions, and Groq-hosted models.
Hosting
Free tiers only. The first request after a quiet spell can take 50 seconds while the server wakes up.
Access
Reading is open. Creating test cases and runs needs an API key.
Not yet
Runs execute inside the API process. A restart mid-run leaves that run stuck, and a separate worker is still to do. The judge can also be fooled by instructions hidden inside an answer.
